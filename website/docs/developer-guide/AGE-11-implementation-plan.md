# AGE-11 — технический NO-GO для текущего контракта `agy -p`

## 1. Статус и область

**Согласованный вердикт Spec: NO-GO для перехода в Dev.** У официального `agy -p` нет документированного нативного протокола передачи role/tool history и передачи управления инструментом Hermes. Документированный финальный JSON даёт возможный **явный текстовый bridge**, но для него не установлен поддерживаемый запрет всех действий собственного агента **до передачи prompt**. В частности, `send_message` документирован как всегда включённый для custom agent, а публичные правила разрешений не устанавливают для него запрета. Это не доказательство того, что конкретный вызов `send_message` исполнится в headless; это конкретный непокрытый путь, несовместимый с требуемой гарантией. Даже подтверждённый вход не закроет этот технический критерий. Отдельно Google явно не поддерживает квоту личных AI Pro/Ultra для этой интеграции.

Проверено 25 ноября 2026 года: [AGE-11](https://linear.app/agentseeai/issue/AGE-11/gemini-directsdk-cherez-antigravity-cli-agy-p), Planning, `da2d02d1-441f-4d16-95b2-bcb79ba032e4`, workspace `3f1ad917-49a9-4d06-aecc-ce84d7a5f598`; [draft PR #7](https://github.com/agentready-tech/hermes-agent/pull/7). Hermes: `mikearlashkin/age-11-gemini-directsdk-cherez-antigravity-cli` START `66cd20dc4c8aedd5bbcfd971c2d19b1dd32cd757`, parent `codex/agentready-runtime` `acdcdbb2dfc8ef2fe0cc5ff31a1e01be4962038f`. Panel: `AgentReady` read-only detached на `main` `3286e53a4fb1684271bfa9f6b3dff1586de6334d`. Google CLI: официальный `linux_amd64` `1.5.17`, не утверждение о последней или будущих версиях.

Требуется отдельный процесс `agy -p` на **каждый запрос модели**, в том числе запрос после результата инструмента внутри одного хода; поток JSON; Hermes владеет историей, запуском инструментов и ходом. Штатный экран моделей Panel, auth только профиля сотрудника; обычный ответ, tool → result → продолжение той же сессии Hermes, истечение авторизации, два разных сотрудника. Выбор модели в Panel не равен успешному подключению или запросу к модели. Не рассматриваются API/Vertex/ACP, иной тариф, native agent как исполнитель, auto-approve, подавление ошибок, скрытые флаги/контракты и fallback на другой маршрут для демонстрации успеха. В Spec не было реального входа, ввода/копирования credentials, оплачиваемых вызовов, установки community plugin, продуктовых изменений, тестового deployment, merge или production. Наблюдение ошибки auth не означает успешный тест истечения существовавшего входа.

## 2. Контракт Google и проверка границ

Первичные источники: [Headless](https://antigravity.google/docs/cli/headless/) (§ Stream prompts from stdin, Unsupported messages, Structured output in the stream, Permissions in headless mode), [CLI reference](https://antigravity.google/docs/cli/reference/), [Subagents — CLI](https://antigravity.google/docs/subagents?app=cli), [Build plugins](https://antigravity.google/docs/build-plugins/) (§ Lifecycle hooks, Subagents, MCP servers, Precedence and Trust), [Permissions — CLI](https://antigravity.google/docs/permissions?tab=cli) и [FAQ — third-party agents](https://antigravity.google/docs/faq/#can-i-use-antigravity-cli-headless-mode-in-third-party-coding-agents-or-automate-account-switching).

**Локальный артефакт E1 — CLI.** Повторно сверены SHA256 бинаря `f3f384bd2c15a74a036ebc3b0a2f48695cc6e56523ba0f9524fb6e4c4adb3baa` и SHA512 архива с `linux_amd64.json`: `71a967aa16e0ab5d87196bcd6772130bdab55b2fd768cd24d21b1da401ff9f60280b976cad3dc14a2d646233b0eaf8caf87c490eed73044d54550cbb3d8d67d2`. `agy-help.txt` подтверждает перечисленные режимы; нет аналога `--tools ''` / `--strict-mcp-config` / `--no-session-persistence` в проверенной справке. Bounded проверки оркестратора: `--tools ''` отвергнут (2); `--print-timeout` использует duration (`2s`, не `2`); в чистом окружении plain print, ограниченный внешним 10s timeout, дал `result ERROR`, ноль ходов/токенов и запрос входа без его открытия; streaming input без auth дал (1), `result ERROR`, ноль ходов/токенов. Это подтверждает границу транспорта и prerequisite, не успешное чтение ролей, модель, permissions или истечение auth. Исходный отрицательный schema probe с неизвестным `enableTelemetry` доказывает лишь отказ validation settings; не используется как аргумент за/против schema. Сырые auth-логи и URL не читались и не включены.

**Дополнительный E1 — validation/discovery до auth.** Позиционный `-p TEXT` вместе с `--input-format stream-json` отклоняется перед auth, а не игнорируется молча. В пустом scratch workspace с `.agents/agents/age11-inert.md` (`mainAgent: true`, `subagent: false`, `tools: []`, `commandExecutionPolicy: "off"`, `inheritMcp: false`, `inheritCustomizations: false`, `skills: []`) отрицательный контроль `--agent age11-intentionally-missing` дал rc 1, unknown agent с `age11-inert` в списке и ноль ходов/токенов. Выбор `--agent age11-inert` с `--settings` (`agentMode: ""`, `toolPermission: "strict"`, `useG1Credits: false`), валидной `--json-schema`, stream-json на обеих сторонах и EOF stdin прошёл validation/discovery до auth, после чего внешние 5 s дали rc 124, `result ERROR`, ноль ходов/токенов, без `init`. Manifest и ограниченные поля stdout прочитаны повторно. Это не подтверждает, что эти фильтры эффективны в ходе либо что schema соблюдается моделью. По документации `send_message` адресует parent/subagent/peer по известному conversation ID и может разбудить простаивающий агент; реальная достижимость адресата в этом one-shot не проверялась. [Официальный Authenticate](https://antigravity.google/docs/install?tab=cli#authenticate) описывает native OS keyring и локальный fallback; очистка/подмена HOME сама по себе не доказывает изоляцию keyring/OS identity.

Фикстура не часть diff и scratch очищается автоматически; ниже условия и результат, не обещание долгосрочного доступа к файлу.

Это проверка локальной упаковки, разбора и координации **в фикстуре**, не семантики модели, нативных ролей Google, безопасности `agy`, конвейера Hermes, уборки дерева дочерних процессов, квоты или QA.

## 3. Существующий код: путь выбора, запуска и ошибки

Здесь пути Hermes относятся к START, пути Panel — к указанному detached SHA; это статическая трасса действующих провайдеров и точек расширения, не описание реализованного Gemini.

1. **Panel и доверенная цель.** `apps/control-plane/components/agent-details.tsx:127` открывает штатный `AgentSubscriptions`; `components/agent-subscriptions.tsx:30–87,111–164,176–187` привязывает `ComputerRpc` к выбранному `environmentId` и каналу `subscriptions`. Вызовы: `status`, `models`, `login.start/poll/code/cancel`, `select`, `disconnect`; метода `subscriptions.activate` на этих SHA нет. `subscription-protocol.mjs:10–44` — allowlist методов, провайдеров (`openai`/`claude`, дополнительно `managed` для select) и параметров; адрес, home, executable и токен не задаются payload. `server.mjs:56–65` держит проверку на loopback; `app/app/api/environments/[environmentId]/computer/authorize/route.ts:14–40` авторизует связь агентским credential на тот же environment, а пользователя — по сессии, `agentAccess` и `canConfigure` без поддержки. `computer-relay.mjs:101–110,169,285–319,342` связывает reverse channel с тем же `environmentId`, link и зарегистрированным agent; требует capability. Штатный Google browser login и Workspace не являются auth Antigravity CLI.
2. **Authoritative home и auth.** Provisioner размещает профиль в `shared-hermes/profiles/<environmentId>` (`AgentReady/docs/AGENTSEE_WORKER_BOOTSTRAP.md:6–29`); `gateway/run_runtime.py:465–482` запускает и останавливает Panel connector существующего владельца профиля. `hermes_runtime/standalone/panel.py:118–151,234–255,275–318,342+` связывает channel со своим `home`, credential и `Subscriptions(home, auth)`; `GatewayPanelAuth(home)` обслуживает shared режим, `NativeScreenAuth` — dashboard-вариант. Не библиотека и не overlay: `hermes_runtime/standalone/panel_subscriptions.py` — владелец RPC на этом SHA. `status` возвращает limited DTO без токена или path; `models` под `profile_scope(self.home)` загружает каталог для подключённого профиля. OpenAI идёт в штатный OAuth API; Claude устанавливает `subscriptions/claude` mode `0700`, сохраняет `claude_config_dir` в `config.yaml`, запускает native login с изолированным env, `poll` сверяет тот же `sessionId`/provider и повторный native logged-in status, `cancel` гасит попытку, `disconnect` требует предварительно снять выбор и проверяет native logout exit (`panel_subscriptions.py:26–74,85–170,224–264`, `panel_claude_login.py`). Это авторитетные события Claude/OpenAI, не спецификация Google login/revoke. `tools/environments/local.py:394–435` умеет собирать окружение для явно указанного `target_home` без наследования чужих provider credentials; Unix `HOME`, keyring, cwd, permissions, lifecycle и auth namespaces `agy` требуют отдельного контракта, а не подстановки одного `HERMES_HOME`.
3. **Выбор и подтверждение.** `panel_subscriptions.py:172–222` после проверки connected + model ID пишет `model.provider/default` в `self.home/config.yaml` через atomic replace, ведёт разрешённый managed route/fallback. В shared gateway пишет `model_selection_revision` и отвечает `saved/deferred`; это квитанция сохранения, не применения. `hermes_runtime/adapters/main_model.py:9–48` на следующем штатном main turn сверяет home/profile и session key, принимает revision нужного вида один раз, устойчиво пишет `_RECEIPT` вместе со снятием override, затем очищает cache/one-turn overrides и резолвит runtime. Другая цель/повтор/отсутствие пригодной revision не очищают override через этот путь. Standalone dashboard вместо этого получает `session.resume` для `agentready_home` и делает `config.set` с фактическим session ID; RPC error не выдаётся за применение уже записанного config. Ни существующий managed fallback, ни отдельный вызов на другом провайдере не закрывает AGE-11. Текущее продуктовое правило и оба маршрута сохранения не менялись.
4. **Модель, child и ход.** `providers/base.py:326–349` — `ProviderProfile.create_client`; `hermes_cli/runtime_provider.py:1131` / `runtime_provider_backends.py:252–278` резолвят `external_process` в chat-completions runtime с `command/args`. `agent/agent_runtime_helpers.py:1829–1858,1963–1979` выбирает custom client до штатных HTTP/Gemini клиентов; ошибка создания/`None` дают fall-through. Для заблокированного адаптера нельзя считать такой fall-through безопасным отказом или разрешить уход на API. `agent/turn_tool_round.py:113–166` кладёт assistant call в каноническую историю и вызывает `_execute_tool_calls`; следующий запрос строит Hermes, а `agent/turn_finalizer.py:653` сохраняет историю. Это нужная точка для hand-off при наличии контракта; не требуется отдавать управление native `--conversation`. `docker/Dockerfile.subscriptions:7–15` пинит Claude plugin и binary; аналогичная утверждённая поставка agy на этих SHA отсутствует. Общее приложение работает в shared pod — изоляция CWD/HOME и остановка процесса не вытекают из отдельного sandbox сотрудника.
5. **Ошибки.** Ошибка login/status на границе `Subscriptions.bridge` → RPC: ожидаемая публичная 400 или фиксированная 503 без сырых upstream исключений (`panel_subscriptions.py:26–39`); `AgentSubscriptions` отображает RPC error своим UI. Ошибка **запроса модели** — отдельный путь: custom client → `agent/turn_api_error.py:111` / `agent/error_classifier.py:724–740,974+` (есть provider classifier) → `agent/error_surface.py:209–230` и поток чата. Для Gemini отсутствуют стабильный безопасный auth-expired сигнал от официального CLI, маппинг и реальный readback. `result ERROR` и наличие login prerequisite без предыдущего входа не различают expiry, revoke, первый вход и временную сеть; не заменять этим отдельный критерий. Ни login URL, ни stderr, ни auth material не должны попасть в transcript, логи Panel или профиль другого сотрудника.

## 5. Чеклист снятия блокировки (не задачи Dev)

1. **Технический unblock, до Dev.** Предмет запроса к Google CLI maintainer: для официального `agy -p` с pin версии/артефакта нужен либо задокументированный host-owned typed role/tool-result hand-off без исполнения CLI, либо задокументированный single-request print режим «только inference», пригодный для финального JSON Schema bridge. В обоих случаях нужен авторитетный контракт до first prompt: кто и на каком lifecycle шаге обеспечивает запрет native actions, включая `send_message`, startup/hooks, MCP discovery/startup, skills/plugins и все источники настроек, с fail-closed отказом для неподдерживаемой версии/конфигурации. Нужны сведения по local persistence/state, effective suppression и безопасные vendor-provided доказательства, не post-hoc события или лог-фильтр. Сверить Headless/Permissions/Build plugins и pin `agy`, а не менять `providers/base.py` или Panel. Пока нет именно такого контракта, Dev остановлен.
2. **Независимый unblock входа/квоты.** Даже при выполнении п. 1 постановщик/оркестратор получает официальное подтверждение того, что третьесторонний сценарий разрешён в исходных границах, каким штатным способом выполняются login, status и logout, кто несёт квоту, кто подтверждает expired/revoked, какие dirs/keyring принадлежат профилю и как подтверждается отмена. Сверить FAQ и capability против `panel_subscriptions.py`, `panel.py`, `tools/environments/local.py`. Наличие device UX, локального token или другой подписки не заменяет это доказательство; пока личный маршрут не поддерживается, не менять тариф или контракт без отдельного решения постановщика.
3. **Повторный go-review Spec.** После п. 1 оркестратор и независимый технический владелец сверяют pin Google, где проходит запрет действий и чем он проверяется. Отдельно согласуемый будущий авторизованный маршрут может обосновать независимые транспортные работы с инертным входом без ожидания квоты. Для плана auth/Panel, интегрированного решения и допуска полного QA необходим также п. 2: оба режима Panel, пер-профильный lifecycle и один разрешённый CLI режим для всех K1–K8. Этот документ не даёт мандата реализовать частичную плитку, bridge или runtime.
